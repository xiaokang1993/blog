## 一、从一张图说起

前阵子看到一张图，标题是《Agent 构成图解》，副标题很直白："以符箓为喻，理解智能体的关键组件"。
![Agent 构成图解：以符箓为喻](/blog/images/agent-fu-map.jpg)

它把一张符拆开，每一块对应 Agent 的一个部件：

| 符箓部位 | 对应组件 | 图上的说明 |
| --- | --- | --- |
| 符头 | API Base URL | 服务地址 |
| 神明名号 | Model ID | 模型标识 |
| 敕令 | API Key | 访问凭证 |
| 天柱 | System Prompt | 系统指令 |
| 地柱 | User Prompt | 用户指令 |
| 所请事项 | Goal | 任务目标 |
| 符胆 | Skill | 可复用技能 |
| 风火轮 | Tool Call | 工具调用 |
| 剑诀（符脚） | Output / Loop | 输出与迭代 |
| 捆仙绳 | Agent Harness | 运行与控制框架 |

图下方还有一行黄底黑字，问得很实在：**"我要请哪个神仙。"**

这张图是好玩的，但它不只是好玩。它恰好踩在了一个真问题上：**为什么我们总在用符咒解释大模型？** 而这个问题的答案，比"因为都像玄学"要有意思得多。

## 二、先把符说清楚

要判断类比成不成立，得先知道被类比的东西长什么样。

符箓并不是随手涂鸦。宋元以后的道书里，符的结构是相当规整的，通常分为三段：

- **符头**：开头的标记，常见"三勾"，象征三清。符头决定了这张符"归谁管"——不同派别的符头暗号不同，走错门就不认。
- **符胆**（也叫符心）：符的核心，写所要沟通的神明名号与具体事项。一张符"灵不灵"，多半看符胆。
- **符脚**：收尾的笔势，决定这张符往哪里去、怎么落地。

正文两侧常配"天柱""地柱"，类似给整张符立一个上下边界。开头还要有"敕令"二字——这不是修辞，"敕"是自上而下的命令，是**授权声明**：我这张符，是奉某位尊神的命令而来，不是我自己要办这事。

再往下追一层，符的成立依赖三个东西：

1. **形式**：笔顺、结构、朱墨、方位，一样不能错；
2. **授权**：没有"敕"，符只是纸上的墨；
3. **传承**：符要经由师授，脱离法脉，同一张符也只是图案。

现在回头看那张 Agent 图，会发现它抓得挺准：`API Base URL` 是符头（决定你连的是哪个门派的服务端），`API Key` 是敕令（没有它，请求只是废纸），`Model ID` 是神明名号（请错了，事情办不成），`System Prompt` 是天柱（立规矩），`User Prompt` 是地柱（具体差事），`Skill` 是符胆（真正决定这一次灵不灵）。

甚至连"我要请哪个神仙"这句话，翻译成工程语言就是：**选哪个模型、用哪个 Provider**。这是每个新项目开局第一件要定的事，而它经常被当成最不重要的事。

## 三、类比成立的三处硬连接

好玩之外，这个类比真正有意思的地方在于：它不是"看起来像"，而是在三个结构点上确实同构。

### 3.1 形式即接口

符的第一个特征是：**格式不可省**。同样的意思，写歪了就是废纸；写对了才"通"。

大模型也一样。你的意图必须被编码进模型能接受的格式里：chat template、tool schema、JSON mode、system/user 分界。差一个字段，工具调用就失败；system 里多一句"你应该"，行为就跑偏。

这不是巧合。符是一种**协议**——人与神之间的协议；prompt 也是协议——人与模型之间的协议。协议的共同点是：内容可以模糊，形式必须精确。

### 3.2 敕令即凭证

符的效力从哪来？从"敕"。道士本人没有权力命令神明，他借用的是更高位的授权。

LLM 调用里的 `API Key` 也是完全一样的东西：模型本身没有义务回应你，是凭证让这次调用合法。而 Agent 更进一步——它有工具调用权限，能改文件、能发请求、能跑命令。这时候"敕令"就不只是通行证，而是**授权范围**：这个 key 能做什么、不能做什么、能花多少钱。

道教讲"符不轻授"，工程上讲"最小权限"。说的是一件事。

### 3.3 符胆即可复用知识

一张符的"核心效验"在符胆。符胆不是每次现编的，是有传承的固定写法：某个法事用某个组合，反复使用，稳定有效。

Agent 里的 `Skill` 扮演的正是这个角色：把"这类任务该怎么做"沉淀成可复用的指令包，遇到匹配的场景就调用，不用每次从零描述。omp、Claude Code 这类工具的 skill 机制，本质就是把"师父口传"变成"文件可加载"。

更妙的是，这张图把 `Tool Call` 标成"风火轮"——不是符的一部分，而是**被驱使的脚力**。工具不是知识，工具是执行力；风火轮不会自己跑，得有个人踩着它。

## 四、类比在哪里断了

但这类比不能推太远。推过头，就变成技术玄学。

### 4.1 符的因果是交感，模型的因果是统计

符咒背后的逻辑是交感巫术：相似产生相似，接触延续接触，符号与所指之间存在实在的联系。写对了名字，就"连上"了那位神。

大模型没有这层意思。它做的是条件概率：给定上文，下一个 token 最可能是什么。prompt 里的"你是资深安全工程师"，不是真的召唤了一个工程师，而是把输出分布推向训练数据里"资深安全工程师写的文本"那一带。

所以一个关键区别：**符的效力是宣称的，模型的效力是可测的。** 符灵不灵，只能事后归因；模型行不行，可以跑 eval、可以回归测试、可以看 diff。

### 4.2 符是封闭的，模型是开放的

符有明确的完成态——写完就完了，一张符对应一件事。错了要重画。

Agent 是循环：输出 → 观察 → 修正 → 再输出。图上把 `Output / Loop` 标成"剑诀（符脚）"，其实这里已经开始勉强了：符脚是收笔，是终结；而 Agent 的 loop 是**没有终点的迭代**，直到任务达成为止。

真正的符不会自我修正。这是两者最大的分岔。

### 4.3 符要求"不变"，模型要求"变化"

符的价值在稳定：三年后同一张符还是同一张符，改了就不灵。

模型的价值恰恰在泛化：同一句 prompt 换个上下文，它应该给出不同的合理回答。你想让它"照符办事"，它偏偏会自己发挥；这是它的缺陷，也是它的全部价值所在。

所以"符咒化使用大模型"——指望一句万能 prompt 解决所有问题、指望背下某个"咒语"就能稳定出好结果——在实践中几乎必然失败。这不是玄学不灵，是**你把一个概率系统当成了确定性系统**。

## 五、为什么我们非要用旧词解释新东西

再退一步看：为什么是符咒？

历史上每次出现真正陌生的技术，我们都先用旧的隐喻把它接住：

- 电报是"千里传音"，电话是"无线的口"；
- 计算机是"电子大脑"，内存是"记忆"；
- 互联网是"信息高速公路"；
- 大模型是"会说话的神谕"，于是 prompt 变成"咒语"，Agent 变成"符"。

隐喻不是装饰，是**认知脚手架**。没有它，新东西无处安放——你没法向一个没用过的人解释 transformer，但你可以说"它像个特别会接话的人"。

问题在于，脚手架会变成天花板。一旦你把模型当成符，你会自然地做出这些事：

- 收藏"神级 prompt"，指望它一次通吃；
- 把失败归因于"咒语不灵"，而不是去查上下文、查工具返回、查权限；
- 追求不可解释的"玄学调参"，跳过可测量的验证。

而如果你把它当成一个**执行者**——有权限边界、有工具、有可观测的每一步、有可验证的结果——你的工程直觉就会自动回到正确轨道上。

那张图真正高级的地方，其实是它的落款："概念类比示意·具体架构以实际系统设计为准。" 做类比的人自己知道边界在哪。

## 六、类比该怎么用

我把这张图当成一个好用的**教学工具**，因为它一眼就能讲清三件工程上容易含糊的事：

1. **分层的必要性**：符头、符胆、符脚各司其职，混在一起就废了。同理，Base URL、模型、系统指令、用户指令、技能、工具，每一层都该独立可换。
2. **授权是有边界的**：敕令不是万能通行证，它限定"奉谁的令、办什么事"。`API Key` 也一样，最小权限永远优先于方便。
3. **核心可复用**：符胆可以传承，Skill 可以沉淀。团队真正的资产不是某一次 prompt，而是积累下来的技能库和规则文件。

而它不该被用来回答的问题是："**为什么模型能work？**" 这个问题只能靠概率、靠数据、靠评测来答，符咒给不了答案。

## 七、结语：符号不生效，接口生效

符咒与符咒之外，其实有一条更普遍的线索：**人类一直在用符号操作世界**。

语言学家把这叫"言语行为"——说"我宣布"就真的宣布了，说"我承诺"就真的承诺了。命令、授权、命名，这些行为不需要物理动作，只需要正确的符号在正确的场合被正确的人说出。"敕令"就是最典型的一种：它不描述世界，它改变世界。

大模型的 prompt 有类似的一面：你不是在描述你想要什么，你是在**设定一个让某种输出成为可能的条件**。写"不要修改任何文件"，和写"只调查报告"，得到的是两种不同的系统状态。

但差别也很清楚：言语行为的效力来自社会制度与共同承认，符咒的效力来自信仰，而模型的"效力"来自训练分布与工程约束。前两者是意义问题，后者是接口问题。

所以我的结论是：**符咒是个好隐喻，但不是好解释。**

用它理解 Agent 的构成、权限与复用，非常趁手；用它理解模型为什么有效，会把你带进沟里。

至于"我要请哪个神仙"——这个问题在两边都成立，而且两边的答案都一样朴素：**先看你有没有那个资格，再看你要办的是什么事。**
